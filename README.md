##   这是什么？

> **QSYS 是一个能够自我进化、自我迭代的全自动量化交易系统**

### 系统简介

**QSYS**（Quantitative System）是一个**全流程自动化**的量化投资系统。它将传统量化研究中分散的因子挖掘、策略构建、回测验证、实盘交易等环节，整合成一个**自我进化、持续学习**的智能系统。

传统量化研究需要研究员花费数周甚至数月的时间去发现一个有效的Alpha因子，然后手动验证、组合、测试。而QSYS通过**遗传算法**和**机器学习**，可以**每天自动生成数百个因子候选**，自动验证其有效性，并自动构建策略组合。

**QSYS 的核心理念是：让机器做机器擅长的事情，让人类专注于决策。**

### 核心特性：三大革命性突破

#### 革命一：全流程自动化

##   核心功能

### 1.   因子演化引擎 (LoopEngine)

**自动发现Alpha因子**：基于遗传算法 + LLM 引导，自动生成、验证、筛选因子

```python
# 系统自动生成的因子（无需人工编写）
le_影线_5f5871 = sub(
    decay_linear(sub(decay_linear(roc(open,200),200), sign(amount)), 200),
    sign(delta(ts_min(ts_max(lower_shadow,120),20), 200))
)

# 系统每天生成数百个因子候选，自动验证有效性
```

**核心能力**：
- **遗传算法 + LLM 双引擎**：突变/交叉/微调 + LLM 引导生成
- **多类型因子挖掘**：量价、资金流、板块轮动、龙虎榜、盘口异动、指数、爆量抢筹（7大类）
- **自适应预算**：根据历史成功率动态调整算子权重
- **FSA失败模式库**：避免重复尝试相同骨架结构
- **硬闸门验证**：IC/ICIR/胜率/夏普/回撤多重过滤
- **因子衰减检测**：滑动窗口监控IC趋势，自动降权衰减因子

**遗传算法详解**：

| 操作 | 说明 | 概率 |
|------|------|------|
| **突变 (Mutate)** | 随机选取非根节点，替换为新随机子树（深度≤6） | 25% |
| **交叉 (Crossover)** | 两棵父本树交换匹配维度的子树 | 25% |
| **微调 (Perturb)** | 窗口参数微调，沿历史成功方向滑动 | 15% |
| **随机生成** | 全新随机表达式树 | 15% |
| **LLM 引导** | DeepSeek 生成探索/利用平衡的因子 | 20% |

自适应预算机制：每轮结束后，根据各操作的历史成功率调整概率（+2% / -2%），上限45%，下限5%。

**表达式树系统**：

```
字段（40+）：
├── 量价基础：open, high, low, close, volume, amount, vwap, overnight, amplitude, shadow
├── 资金流：main_net_pct, super_net_pct, big_net_pct, small_net_pct, net_inflow_ratio
├── 板块轮动：sector_momentum, sector_net_flow, sector_breadth, sector_rank
├── 龙虎榜：lhb_net_buy, lhb_inst_ratio, lhb_hot_count, lhb_win_rate
├── 盘口：bid_ask_ratio, outer_inner_ratio, quantity_ratio_dev, tick_vol_ratio
├── 指数：idx_beta, idx_rs, idx_vol_ratio, idx_corr, idx_alpha
└── 爆量抢筹：vol_spike, bid_pressure, outer_dominance, accumulation_composite

算子（18个）：
├── 算术：sub, mul, div
├── 一元：abs, sign, rank_cs
├── 滑窗保持：ma, ts_min, ts_max, decay_linear, std, skew, delta, roc, ema
```

**LLM 引导生成**：
- 双目标轮换：探索（填充覆盖不足的机制族） vs 利用（深挖已验证有效的机制族）
- 使用 DeepSeek Chat 模型，fail-open（LLM 不可用时回退随机生成）
- LLM 审查代理：独立审查者检查维度一致性、除零风险、窗口合理性、经济可解释性
- 每轮预算：10次审查，50%采样概率

**衰减检测**：
```
滑动窗口监控：
  近60天IC  vs  历史IC（500天）
      │
      ▼
  IC衰减率 = (近60天IC - 历史IC) / |历史IC|

  衰减阈值与权重：
  ├── 正常：衰减率 ≥ -30%  → 权重 1.0
  ├── 轻度衰减：-50% ≤ 衰减率 < -30%  → 权重 0.7
  ├── 中度衰减：-70% ≤ 衰减率 < -50%  → 权重 0.4
  └── 重度衰减：衰减率 < -70%  → 权重 0.2（软惩罚，非硬退役）
```

### 2.   因子评估系统

**严格的因子验证流程**：

```
因子候选 ──▶ 规则审查 ──▶ LLM审查 ──▶ 去重 ──▶ 闸门验证 ──▶ 注册评分
    │           │           │          │          │          │
    │           │           │          │          │          └── 5维评分 + 可信度
    │           │           │          │          └── 12道硬闸门 + FDR校正
    │           │           │          └── MD5哈希去重
    │           │           └── 独立审查者（维度/窗口/经济意义）
    │           └── 深度≤6，维度一致，无除零
    └── 18个算子 × 40+字段 × 12个窗口
```

**12道硬闸门（gates.py）**：

| # | 闸门 | 阈值 | 说明 |
|---|------|------|------|
| 1 | \|IC\| | ≥ 0.02 | 沪深300池校准值（全市场用0.03） |
| 2 | IC p-value | ≤ 0.01 | Benjamini-Hochberg FDR校正 |
| 3-4 | 2025年超额+夏普 | > 0, > 0.5 | 年度窗口验证 |
| 5-6 | 2026年超额+夏普 | > 0, > 0.5 | 年度窗口验证 |
| 7 | Calmar比率 | ≥ 1.0 | 收益/最大回撤 |
| 8-9 | 近9月/12月超额 | > 0 | 长周期稳定性 |
| 10-11 | 与因子库相关性 | < 0.70 | 去冗余 |
| 12 | OOS IC均值+胜率 | ≥ 0.01, ≥ 50% | 样本外表现 |

**多周期胜率标准（统一口径）**：
```
持有期: 1日 / 5日 / 20日 / 60日 / 120日
基准:   等权均值（非中位数）
成本:   双边千一（0.25%）
步长:   5日（与持有期对齐）
```

**Walk-Forward 验证（factor_eval.py）**：
```
估计窗口: 250个交易日
应用步长: 5个交易日
成本模型: 0.25% 双边
输出指标:
├── 年化收益 (ann_return)
├── 夏普比率 (sharpe)
├── 最大回撤 (max_drawdown)
├── 盈亏比 (profit_factor) = 总盈利 / |总亏损|
├── 平均盈亏比 (win_loss_ratio) = 平均盈利 / 平均亏损
├── 扣费后胜率 (win_rate)
├── 月度胜率 (monthly_winrate)
└── 最大连续亏损月数 (max_consec_loss_months)
```

**回测可信度评分（backtest_credibility_score）**：

6维度 100分制：

| 维度 | 分值 | 评分标准 |
|------|------|----------|
| IS/OOS差距 | 25 | 胜率越高越好 |
| 样本量 | 15 | ≥50期满分 |
| 夏普比率 | 20 | ≥2.0满分 |
| 最大回撤 | 15 | >-5%满分 |
| 盈亏比 | 15 | ≥2.0满分 |
| 月度胜率 | 10 | ≥60%满分 |

评级：A(≥80) / B(≥65) / C(≥50) / D(≥35) / F(<35)

**5维因子评分（library.py）**：
```
总分 = IC质量(30%) + IC稳定性(25%) + 一致性(20%) + 使用度(15%) + 新鲜度(10%)

IC质量 = min(1.0, |IC| × 10 × 0.5 + IC胜率 × 0.5)
IC稳定性 = IC胜率（越接近1越稳定）
一致性 = Top组胜率
使用度 = min(1.0, 总使用次数 / 10)
新鲜度 = max(0.1, 1.0 - 天数 / 180)（180天衰减）
```

**FDR多重检验校正**：
```python
# Benjamini-Hochberg 校正（alpha=0.05）

# IC p值计算（无需scipy）
p_value = ic_pvalue(ic_mean, ic_std, n_days)
# 使用正态近似：t = ic_mean / (ic_std / sqrt(n))
```

### 3.   策略包自动生成

**从因子到策略的自动化流水线**：

```python
# 1. 因子筛选：从因子库中筛选Top因子（ICIR > 0.2）
# 2. 组合构建：贪心选择 + MMR去冗余
# 3. Walk-forward验证：样本外胜率 ≥ 50%
# 4. 质量门槛：OOS胜率 + 实战差距 < 25%
# 5. 自动入库：保存到strategies表

# 多包投票机制（降低过拟合风险）
pack1_stocks = compute_pack_picks(alpha101, codes)  # Alpha101精华
pack2_stocks = compute_pack_picks(short5, codes)    # 短线5日
pack3_stocks = compute_pack_picks(stable, codes)    # 稳健低波

# 取至少2票的交集
final_stocks = intersection(pack1, pack2, pack3)
```

**策略包生成流程**：
1. **因子筛选**：从因子库中筛选Top因子（ICIR > 0.2）
2. **组合构建**：使用贪心选择 + MMR去冗余，构建5-8个因子的组合
3. **Walk-forward验证**：滚动窗口验证，确保样本外胜率 ≥ 50%
4. **质量门槛**：OOS胜率与实战差距 < 25%，避免过拟合
5. **自动入库**：保存到strategies表，供选股使用

**组合构建算法**：
- **贪心选择（Greedy）**：前向逐步选择，每次添加最大化OOS净超额胜率的因子
- **MMR采样（Maximal Marginal Relevance）**：质量加权softmax + 相关性惩罚，生成12组候选，选最优OOS表现
- **去相关**：相关性 > 0.7 的因子对，保留ICIR更高的那个

**多包投票机制**：
- **Top3策略包投票**：Alpha101精华、短线5日、稳健低波等
- **取至少2票的交集**：降低过拟合风险
- **动态权重**：根据实战表现调整各策略包权重
- **贝叶斯收缩**：`shrunk = (observed × n + 0.5 × 10) / (n + 10)`（避免小样本偏差）


**学习机制**：
1. **自动分析失败原因**：系统自动分析每次失败的根本原因
2. **自动避免重复错误**：将失败模式记录到FSA失败模式库，避免重复尝试
3. **自动优化策略参数**：根据历史表现自动调整策略参数
4. **自动适应市场变化**：根据市场变化自动调整策略组合

**实际效果**：
- **失败模式库**：101,847条失败记录，避免重复尝试
- **隔夜风险**：72.3%的失败与隔夜风险相关，系统自动调整策略避免过度暴露
- **IC边缘失败**：~8,000次IC在0.013-0.019之间，系统考虑是否放宽阈值或改进因子表达式
- **策略包评分**：20个策略包自动评分，持续优化

### 多类型因子挖掘

系统支持7大类因子数据源，每类有专门的帧构建器：

| 类型 | 数据源 | 说明 |
|------|--------|------|

| **资金流** | stock_fundflow_daily | 主力/超大/大单/小单净流入 |
| **板块轮动** | sector_inflow_snapshots | 板块动量/资金流/宽度/排名 |

| **爆量抢筹** | 盘中快照 | 量比异动/委压/外盘主导/吸筹 |

每轮默认挖掘顺序：量价 → 资金流 → 板块轮动 → 指数 → 盘口异动 → 龙虎榜 → 爆量抢筹，每类15个候选。

### 机制族分类


骨架格式：`算子序列@字段集合`，如 `ma-delta@close,overnight`。相同骨架 = 相同结构 = 潜在冗余。

##   因子演化引擎优化方案

### 当前系统分析

| 问题 | 现状 | 影响 |
|------|------|------|
| **因子衰减无检测** | 因子入库后永不退役 | 过期因子持续贡献错误信号 |
| **回测胜率≠实盘胜率** | Walk-forward验证基于历史数据 | OOS 86% → 实战47%，差距39% |
| **无收益风险平衡** | 只关注IC/ICIR，忽略回撤 | 高IC因子可能带来高波动 |
| **多样性不足** | FSA冻结是唯一机制 | 容易陷入局部最优 |
| **算子权重静态** | 字段权重只按频率调整 | 不区分好因子和坏因子的贡献 |

### 优化方案：四大模块

#### 模块一：因子衰减检测系统

**核心思想**：因子的预测能力会随时间衰减，需要实时监控并自动退役。

```
因子衰减检测流程：
─────────────────────────────────────────────────────────────────

  因子IC序列
      │
      ▼
┌─────────────────────────────────────────────────────────┐
│  滑动窗口监控                                            │
│                                                         │
│  近60天IC  vs  历史IC                                   │
│      │              │                                   │
│      ▼              ▼                                   │
│  IC衰减率 = (近60天IC - 历史IC) / |历史IC|              │
│                                                         │
│  衰减阈值：                                              │
│  ├── 轻度衰减: IC衰减率 < -30%  → 降低权重              │
│  ├── 中度衰减: IC衰减率 < -50%  → 标记警告              │
│  └── 重度衰减: IC衰减率 < -70%  → 自动退役              │
│                                                         │
└─────────────────────────────────────────────────────────┘

  实现方式：
  - 新增 factor_decay 表，记录每个因子的衰减状态
  - 每周自动运行衰减检测
  - 衰减因子自动从策略包中移除
```

#### 模块二：实盘胜率优化

**核心思想**：从"回测胜率高"转向"实盘胜率高"，减少过拟合。

```
实盘胜率优化策略：
─────────────────────────────────────────────────────────────────

  当前问题：
  ├── OOS胜率86% → 实战47%（差距39%）
  ├── Walk-forward验证基于历史数据
  └── 无实盘表现反馈机制

  优化方案：
  ┌─────────────────────────────────────────────────────────┐
  │  1. 样本外严格隔离                                      │
  │     - 最近60天数据完全隔离，不参与任何训练              │
  │     - Walk-forward验证窗口后移60天                      │
  │                                                         │
  │  2. 实盘表现反馈                                        │
  │     - 记录每个因子的实盘表现                            │
  │     - 计算实盘胜率 vs 回测胜率的差距                    │
  │     - 差距>25%的因子自动降权                           │
  │                                                         │
  │  3. 多市场验证                                          │
  │     - 在不同市场环境下验证因子                          │
  │     - 牛市/熊市/震荡市分别验证                          │
  │     - 只在多种市场环境下都有效的因子才入库              │
  │                                                         │
  │  4. 因子稳定性评分                                      │
  │     - IC波动率：IC标准差越小越稳定                      │
  │     - IC趋势：IC是否在下降                              │
  │     - IC一致性：不同时间窗口的IC是否一致                │
  └─────────────────────────────────────────────────────────┘
```

#### 模块三：收益风险平衡

**核心思想**：在追求高收益的同时控制最大回撤和波动率。

```
收益风险平衡策略：
─────────────────────────────────────────────────────────────────

  当前问题：
  ├── 只关注IC/ICIR，忽略回撤
  ├── 高IC因子可能带来高波动
  └── 无风险调整后收益指标

  优化方案：
  ┌─────────────────────────────────────────────────────────┐
  │  1. 新增风险指标                                        │
  │     - 最大回撤 (Max Drawdown)                           │
  │     - 夏普比率 (Sharpe Ratio)                           │
  │     - 索提诺比率 (Sortino Ratio)                        │
  │     - 卡玛比率 (Calmar Ratio)                           │
  │                                                         │
  │  2. 多目标评分                                          │
  │     Score = α × IC + β × (1 - MaxDD) + γ × Sharpe      │
  │     其中 α=0.4, β=0.3, γ=0.3                          │
  │                                                         │
  │  3. 风险预算                                            │
  │     - 每个策略包的最大回撤限制: 15%                     │
  │     - 每个行业最大暴露限制: 20%                         │
  │     - 每只股票最大持仓限制: 5%                          │
  │                                                         │
  │  4. 动态止损                                            │
  │     - 基于波动率的动态止损                              │
  │     - ATR止损: 止损线 = 入场价 - 2 × ATR               │
  │     - 时间止损: 持有超过20天自动平仓                    │
  └─────────────────────────────────────────────────────────┘
```

```
  │  4. 时间多样性奖励                                      │
  │     - 长期有效因子获得奖励                              │
  │     - 短期有效因子获得惩罚                              │
```

### 实施计划

### 验证结论（walk-forward OOS 实测，2026-09）

对已过硬闸门的 loopengine 因子做历史时点 T 的样本内计算，检验其与
T 之后（120/250 个交易日）样本外 IC 的关系（n=63~69）：

**结论 1：衰减检测有效。** 轻度/中度衰减组的 OOS IC 在 120 天窗口均接近零或为负
（mild -0.0006、moderate -0.0052），显著差于正常组（+0.0263）；重度组存在市场
状态切换时的集体误报（250 天窗口重度组 OOS +0.0707 明显恢复），故重度衰减采用
父本权重软惩罚（0.2）而非硬退役。

**结论 2：多目标评分原设计有害，已按数据重构。** 过闸因子间样本内夏普/索提诺/
卡玛/回撤与 OOS IC 显著负相关（ρ=-0.45~-0.60，p<0.001）——线性奖励平滑曲线
等于奖励过拟合。修正后：IC 主导（0.8），风险/夏普只保留灾难阈值惩罚（回撤>70%、
夏普<0.5 才扣分），120 天窗口 ρ 从旧版 -0.475 提升到 -0.087（中性），250 天窗口
+0.330（p=0.008）。IC 稳定性/趋势分量经验上反向预测 OOS（trend ρ=-0.47），
仅作诊断展示不计入评分。

**结论 3：过拟合是结构性现象。** 没有任何样本内单指标在两个窗口都正向预测 OOS IC
（ICIR 在 250 天窗口 ρ=+0.735，在 120 天窗口 ρ=-0.26）——单窗口排序指标不可靠，
多目标评分的价值在于风险筛查与诊断而非收益排序。

##   因子生成算法

### LoopEngine 演化引擎架构

LoopEngine 是一个**遗传算法驱动的因子挖掘系统**，每轮执行 10 步流水线，批量处理 `batch` 个候选因子。

```
┌─────────────────────────────────────────────────────────────────┐
│                    LoopEngine 单轮流水线                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Step 1: Build Panel ──── 加载股票池价格/成交量面板             │
│      │                                                           │
│  Step 1.5: Regime Detection ── 市场环境识别                     │
│      │                                                           │
│  Step 2: Family Guidance ── 机制族覆盖度分析                    │
│      │                                                           │
│  Step 3: FSA Recompute ──── 冻结骨架自动机（反同质化）          │
│      │                                                           │
│  Step 3.5: Decay Detection ── 滑动窗口IC衰减检测               │
│      │                                                           │
│  Step 4: Generate Candidate ── 自适应预算选择生成源             │
│      │                                                           │
│  Step 5: Rule Review ──── 结构合法性检查                        │
│      │                                                           │
│  Step 6: LLM Review ──── 经济合理性审查（50%采样）             │
│      │                                                           │
│  Step 7: Dedup ──── 哈希去重                                    │
│      │                                                           │
│  Step 8: FSA Intercept ──── 冻结骨架拦截                       │
│      │                                                           │

│      │                                                           │
│  Step 10: Register ──── 多目标评分 + 注册入库                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.1 遗传算法操作

系统采用 **7种生成源**，通过自适应预算动态调整概率：

| 生成源 | 操作 | 初始概率 | 说明 |
|--------|------|----------|------|
| `mutate` | 突变 | 20% | 随机选取非根节点，替换为新随机子树（深度≤6） |
| `crossover` | 交叉 | 20% | 两棵父本树交换匹配维度的子树 |
| `perturb` | 微调 | 12% | 窗口参数沿历史成功方向滑动 |
| `random` | 随机生成 | 12% | 全新随机表达式树（加权字段选择） |
| `llm` | LLM引导 | 16% | DeepSeek生成探索/利用平衡的因子 |
| `mutate_op` | 算子变异 | 10% | 改变算子类型（如ma→ema），保持结构 |
| `perturb_field` | 字段扰动 | 10% | 切换相关字段（如close→open） |

**自适应预算机制**：
- 维护最近50次（源，采纳）记录
- 每轮结束后调整：最优源+2%，最差源-2%
- 下限5%，上限45%，归一化后重分配

**表达式树系统**：
```
字段（40+）：
├── 量价基础：open, high, low, close, volume, amount, vwap, overnight, amplitude, shadow
├── 资金流：main_net_pct, super_net_pct, big_net_pct, small_net_pct, net_inflow_ratio
├── 板块轮动：sector_momentum, sector_net_flow, sector_breadth, sector_rank
├── 龙虎榜：lhb_net_buy, lhb_inst_ratio, lhb_hot_count, lhb_win_rate
├── 盘口：bid_ask_ratio, outer_inner_ratio, quantity_ratio_dev, tick_vol_ratio
├── 指数：idx_beta, idx_rs, idx_vol_ratio, idx_corr, idx_alpha
└── 爆量抢筹：vol_spike, bid_pressure, outer_dominance, accumulation_composite

算子（18个）：
├── 算术：sub, mul, div
├── 一元：abs, sign, rank_cs
├── 滑窗保持：ma, ts_min, ts_max, decay_linear, std, skew, delta, roc, ema

```

### 1.2 市场环境识别（Regime Detection）

基于多指数综合判断当前市场状态：

**输入数据**：沪深300（40%）、深证成指（30%）、创业板指（30%），120天回溯

| 维度 | 方法 | 阈值 |
|------|------|------|
| 趋势 | MA5/MA20/MA60排列评分（-1到+1） | 加权平均 |

| 成交量 | 5日均量 / 20日均量 | >1.3放量，<0.7缩量 |
| 动量 | 5日收益*0.4 + 20日收益*0.6 | 复合趋势 |

**分类规则**：
```

牛市：combined > 0.3
熊市：combined < -0.3
```

##   策略生成算法

### 2.1 因子评估体系

**核心指标**：
- **RankIC**：因子值与未来收益的秩相关系数
- **ICIR**：IC均值/IC标准差（因子质量核心指标）
- **分组胜率**：前10%多头组合跑赢中位数的比例

**多周期胜率**：1日、5日、20日（月度）、60日（季度）、120日（半年度）

**默认参数**：
- 前瞻天数：5天
- 估计窗口：250天
- 步进天数：5天
- 相关性阈值：0.70
- 交易成本：0.25%（双边）

### 2.2 前进验证（Walk-Forward）

```
时间轴：|--------估计窗口--------|----前瞻----|
         t-250                   t-5          t

每个验证点t：
1. 估计窗口内计算IC统计量（均值、ICIR、胜率）
2. 推导因子权重
3. 在t时刻对所有股票打分，选Top-N
4. 记录未来5天的超额收益
5. 扣除换手成本后的净超额
```

**缓冲区机制**：前次持仓未跌出Top(top_n + buffer_n)则保留，换手率降低约50%

**输出统计**：
- 年化收益率、夏普比率、最大回撤
- 盈亏比、月度胜率、最大连续亏损月数

### 2.3 权重计算方法

| 方法 | 公式 | 适用场景 |
|------|------|----------|
| 等权 | 1.0 | 基准 |
| ICIR加权 | \|ICIR\| | 主流方法 |
| 胜率加权 | max(winrate - 0.5, 0) | 稳健策略 |
| 均值-方差 | \|IC_mean\| / IC_var | 理论最优 |

**方向自动确定**：IC均值为正→方向+1，为负→方向-1

### 2.4 组合构建算法

#### 贪心组合选择（Greedy Combo）
1. 从空集开始前向选择
2. 每步添加使OOS净超额胜率最大的因子
3. 无改进或达到最大数量（8）时停止

#### MMR组合选择（最大边际相关性）
```
质量分 = 2 * max(winrate - 0.5, 0) + |ICIR| / max|ICIR|
多样性惩罚 = lambda * max_corr_with_selected

采样：温度τ=0.2，12次采样 + 贪心基线
每次采样通过前进验证，选最优OOS胜率
```

#### 相关性去重
- 跨族阈值：0.70
- 同族阈值：0.60（更严格，同机制结构相似）

### 2.5 多目标评分

基于实证校准的权重（IS夏普/索提诺/卡玛与OOS IC负相关）：

| 维度 | 权重 | 计算 |
|------|------|------|
| IC得分 | 80% | min(1, \|IC\| * 10) * 0.5 + IC胜率 * 0.5 |
| 风险得分 | 10% | 最大回撤 ≤ 70% = 满分 |
| 夏普得分 | 10% | 夏普 ≥ 0.5 = 满分 |

**稳定性/趋势**：仅诊断展示，不计入评分（实证为负向预测因子）

### 2.6 回测可信度评分

0-100分等级制（A-F），基于6个维度：

| 维度 | 满分 | 标准 |
|------|------|------|
| IS/OOS差距 | 25分 | 差距越小越可信 |
| 样本量 | 15分 | 前进验证期数越多越好 |
| 夏普比率 | 20分 | ≥ 2.0 满分 |
| 最大回撤 | 15分 | ≤ 5% 满分 |
| 盈亏比 | 15分 | ≥ 2.0 满分 |
| 月度胜率 | 10分 | ≥ 60% 满分 |

### 2.7 FDR校正

**Benjamini-Hochberg FDR**：控制错误发现率在α=0.05

同时测试1000个因子时，约50个会因随机性表现为显著——FDR校正解决此问题。每个因子获得p值（IC均值的t检验）和q值（校正后）。

### 2.8 自动选股算法（v5）

**7步流水线**：

```
1. 因子回测评分 ──── 五维度因子价值评分
      │
2. 实盘胜率 ──── 贝叶斯收缩 + 指数时间衰减（90天半衰期）
      │               最少10笔交易才具统计显著性
      │
3. 策略包投票 ──── 因子所在策略包的加权平均分
      │               3+个包=满额稳健性
      │
4. 综合v5评分 ──── backtest*0.25 + actual*conf*0.25 + ret*conf*0.10
      │               + pack*0.15 + total*0.10 + stability*0.08 + momentum*0.07
      │
5. 类型+族多元化 ──── 每类型最多3个，每族最多2个
      │
6. 相关性过滤 ──── 贪心去相关（0.70阈值）
      │
7. 行业分散 ──── 每行业最多2只
```

### 2.9 策略包管理

**数据库表**：
- `factor_registry`：因子注册表（名称、类型、骨架、族、闸门状态、多目标评分）
- `factor_scorecards`：因子评分卡（每池每日期的评估指标）
- `strategies`：策略包定义（因子组合、OOS胜率、状态）
- `failure_patterns`：失败模式库（101,847条记录）
- `family_live_stats`：机制族实盘统计

**五维度因子价值评分**：

| 维度 | 权重 | 说明 |
|------|------|------|
| IC质量 | 30% | IC强度 × 胜率 |
| IC稳定性 | 25% | IC胜率（一致性代理） |
| 一致性 | 20% | 分组胜率 |
| 使用率 | 15% | 归一化的被选中+交易次数 |
| 新鲜度 | 10% | 首次出现的时效性（180天半衰期） |

### 2.10 反馈循环

```
LoopEngine演化 ──▶ 因子注册表
      │
      ▼
因子评分卡（评估）
      │
      ▼
策略包定义（组合）
      │
      ▼
选股/交易执行
      │
      ▼
经验库（实盘结果）
      │
      ▼ (反馈循环)
├── 实盘胜率 ──▶ 父本选择（机制族实盘加成）
├── 衰减检测 ──▶ 父本选择（衰减因子降权）
├── 市场环境 ──▶ 父本选择（regime加权）
├── 价值评分 ──▶ 父本选择（最高1.5x加成）
├── 失败模式 ──▶ FSA冻结（>30次失败冻结骨架）
```

**关键反馈机制**：
1. **实盘→父本选择**：`family_live_stats()`聚合机制族实盘胜率，偏向有实证表现的族
2. **衰减→父本选择**：衰减因子权重降至0.2-0.7x
3. **环境→父本选择**：当前regime对已知有效族应用乘性权重
4. **价值→父本选择**：五维度价值评分最高可获1.5x加成
5. **失败→FSA**：失败骨架累积>30次或>15%占比触发冻结
6. **重验→策略包**：OOS下降>5%的策略包降级排除

### 数据源详情

#### 1. Qlib本地数据（主要回测数据源）

```yaml
来源: GitHub社区仓库 chenditc/investment_data
格式: Qlib二进制格式 (qlib_bin.tar.gz)
内容: 全A股历史日线OHLCV（前复权）
大小: ~560MB
认证: 无需（公开数据）
更新: 每日17:35自动下载（3个镜像源备选）
路径: /data/qlib/cn_data
用途: 因子回测、策略验证、LoopEngine演化
```

**优势**：数据质量高、格式统一、适合大规模因子挖掘和回测

#### 2. Akshare（新浪财经备选数据源）

```yaml
来源: akshare库（封装新浪财经接口）
格式: DataFrame
内容: 日线OHLCV（前复权）、流通股本
认证: 无需（公开API）
限速: 150ms/请求
缓存: 读写缓存到market_daily表(source='akshare')
用途: 分析展示、Qlib数据不足时的备选
```

**注意**：首次获取较慢，后续使用缓存加速

#### 3. easy-tdx（通达信行情服务器）

```yaml
来源: easy_tdx库（TCP连接通达信行情服务器）
服务器: 6个预选高质量服务器
内容: 日线、1分钟线、Tick级交易数据
认证: 无需（公开行情服务器）
Tick同步: 每10秒一次（job_tick_sync）
集合竞价: 支持（buyorsell=8标记09:15-09:25）
用途: 实时行情、高频数据、Tick分析
```

**特色**：支持集合竞价数据、Tick级精度、实时性强

#### 4. 腾讯财经（实时行情数据源）

```yaml
来源: 腾讯财经HTTP API (qt.gtimg.cn)
格式: JSON/JSONP
内容: 实时行情快照(~3秒延迟)、日内分钟线、流通/总市值、五档盘口
认证: 无需（公开API）
批量: 支持~50只/请求
用途: 实时行情采集、市值计算、盘口数据
```

**优势**：延迟低、数据全、支持批量查询

#### 5. iFinD同花顺（专业金融数据终端）

```yaml
来源: iFinDPy SDK + HTTP API
认证: ✅ 需要（账号密码 或 Refresh Token）
通道: 
  - HTTP通道: Token认证，无会话限制（推荐）
  - SDK通道: 用户名密码，会话限制（-9错误自动冷却10分钟）
内容:
  - 日线OHLCV（前复权）
  - 实时行情（最新/开高低/量额/PE/PB等）
  - 盘中快照（3秒级）
  - 高频数据（1/5/15/30/60分钟线）
  - 基本面（PE TTM/PB/ROE/EPS/BPS/股息率/流通股等）
  - 交易日历（上交所/深交所）
  - 公告数据（含PDF链接）
  - 龙虎榜数据
  - 资金流入（问财查询）
  - 全A股列表（含所有基本面）
  - 指数列表（宽基/行业/主题）
用途: 全市场数据同步、基本面分析、资金流分析
```

**优势**：数据最全面、覆盖最广、专业级质量

**配置方式**：
```bash
# 方式一：环境变量
export THS_IFIND_ACCOUNT="your_account"
export THS_IFIND_PASSWORD="your_password"
# 或
export THS_IFIND_REFRESH_TOKEN="your_token"

# 方式二：settings.json
{
  "ths_ifind": {
    "account": "your_account",
    "password": "your_password"
  }
}
```

#### 6. 东方财富（日内资金流数据源）

```yaml
来源: 东方财富push2 HTTP API (push2.eastmoney.com)
格式: JSON
内容: 单只股票日内(1分钟)资金流（主力/超大/大/中/小单净流入）
数据量: ~240点/天
认证: 无需（公开API）
用途: 日内资金流分析、主力资金监控
```

**优势**：日内资金流粒度细（1分钟）、实时性强

#### 7. 新浪板块数据（行业分类映射）

```yaml
来源: akshare库（封装新浪行业板块接口）
内容: 84个行业分类、板块实时行情（涨跌幅/量额/领涨股）
认证: 无需
采集: 每30秒（sector_flow_collect任务）
用途: 板块轮动因子、行业配置
```

#### 8. LoopEngine帧构建器（复合数据源）

```yaml
来源: 本地SQLite表聚合
构建器:
  - build_fundflow_frames(): 读取stock_fundflow_daily表
  - build_sector_frames(): 读取sector_inflow_snapshots表
  - build_lhb_frames(): 读取lhb_daily表
  - build_tick_frames(): 读取quote_snapshots表
  - build_index_frames(): 读取Qlib指数数据
  - build_burst_frames(): 聚合量价数据
内容: 7种非量价因子类型的评估帧
用途: LoopEngine多类型因子挖掘与评估
```

**特色**：不是直接数据源，而是将多源数据聚合为因子评估帧

##   常见问题

### Q: 如何查看因子演化日志？

```bash
# 查看实时日志
docker compose logs -f qsys | grep "LoopEngine"

# 查看历史日志
docker exec lh-qsys cat /data/scheduler_history.jsonl
```

### Q: 如何手动触发选股？

```bash
docker exec lh-qsys python3.11 -c "
import sys; sys.path.insert(0, '/app')
from scheduler import job_pool_scan
print(job_pool_scan())
"
```

### Q: 如何查看策略包评分？

```bash
docker exec lh-qsys python3.11 -c "
import sys; sys.path.insert(0, '/app')
import library
packs = library.list_strategies()
for name, pk in packs.items():
    print(f'{name}: OOS={pk.get(\"oos_winrate\")}, method={pk.get(\"method\")}')
"
```

### Q: 如何查看失败模式？

```bash
docker exec lh-qsys python3.11 -c "
import sqlite3
c = sqlite3.connect('/data/market.db')
rows = c.execute('''
    SELECT pattern, COUNT(*) as cnt
    FROM failure_patterns
    GROUP BY pattern
    ORDER BY cnt DESC
    LIMIT 10
''').fetchall()
for pattern, cnt in rows:
    print(f'{pattern}: {cnt}次')
"
```
