## 目标与范围

先让回测结果正确、可复现、可解释，并让评估任务持续完成，再补K线、信号与成交联动图。工程验收通过不等于因子盈利或获得交易资格；样本不足、表现不佳也是应当准确输出的结果。

复用现有 factor_eval、strategy_backtest、factor_evaluation_queue、validation_policy、execution_gate 和评估回执，不重建一套平行体系。此次只新增计划，不调整生产参数、启动全量回测、修改交易资格或覆盖已有工作区修改。

## 阶段一：纠正指标与统一计算口径（P0）

交付：共享的收益/绩效计算入口、评估配置说明、修正后的现有报告。

- [ ] 梳理详情页、实验室、静态回测、walk-forward、策略回测、Qlib产物读取各入口，列明收益频率、交易时点、成本、持仓、基准、年化及缺失值处理，标出可比与不可比结果。
- [ ] 将研究前向收益与可执行组合收益分开。日频净值来自逐日持仓估值；非重叠持有期统计按实际周期处理；重叠持仓必须建分批资金账户，禁止直接复利重叠前向收益。
- [ ] 修正详情页错误净值及衍生指标；旧结果保留规则版本和失效原因，不与新版横比。共享计算入口完成前，停止展示该页误导性的策略绩效。
- [ ] 将现有“IC衰减”更名为滚动IC；持有期衰减先提供1/5/10/20日数值报告和有效样本数，图形后补。
- [ ] 明确毛收益、净收益、基准收益、超额收益及超额净值定义，分别标注组合回撤和超额序列回撤；夏普与年化使用声明的频率，基准与持仓日期对齐。
- [ ] 统计和排名按因子版本、规则版本、股票池、样本状态过滤；未经验证和样本不足不进入有效结果默认排行。

验收：可手算样例覆盖恒定价格、单次涨跌、完整开平仓费用、缺失数据、跨年日期、重叠20日标签；同一配置走不同受支持入口的基础收益和指标一致。差异化引擎必须说明假设，不能强行对齐数值。

主要位置：qsys/factor_eval.py、qsys/strategy_backtest.py、qsys/views/p_factor_detail.py、qsys/views/p_factor_lab.py、qsys/views/p_factor_stats.py、qsys/views/p_backtest.py。

## 阶段二：跑通评估队列与覆盖在用因子（P0）

交付：调度根因记录、可持续处理队列、实际吞吐及覆盖报告。

- [ ] 以数据库和日志确认漏跑原因，检查定时入口、生成后唤醒、锁、重启恢复、长任务和同版本去重；不先靠增加频次掩盖问题。
- [ ] 优先覆盖active/shadow策略当前版本因子，同时保留各类型公平性；明确优先策略，防止新因子或到期重评长期挤占首次评估。
- [ ] 先跑小批量真实评估，记录每类型耗时、峰值内存、数据读取量、成功/不足/失败数，再决定批量、时间预算与并发；避免一次读入全库。
- [ ] 提供队列剩余量、运行心跳、最近成功时间、失败原因、重试时间、当前版本首次覆盖率与在用覆盖率；积压清理时间按实际首次评估吞吐估算。
- [ ] 验证进程中断后恢复、同版本重复请求合并、版本变更作废、连续失败阻塞和显式恢复；所有失败仍保留证据。

验收：连续两个实际调度窗口有可核对的起止与回执；在用因子均获得当前版本明确状态，包括样本不足或失败；队列处理数与回执数对账，无残留假运行、重复计算或虚假成功。无需等待全部39,900个评完才能进入下一阶段。

主要位置：qsys/factor_evaluation_queue.py、qsys/scheduler.py、qsys/library.py、qsys/factor_eval_ui.py。

## 阶段三：建立可核账的策略回测（P1）

依赖：阶段一计算口径；输入可用性由阶段二提供。交付：统一配置、完整信号/订单/成交/持仓/现金流水和日净值。

- [ ] 首版限定日频股票多头组合；信号在当日数据可用后生成，默认下一交易日开盘尝试成交。无法取得所需成交价或时点证据时明确失败/降级，不回填理想成交。
- [ ] 明确起止区间、历史股票池、资金、Top-N、调仓日历、权重、持有期、复权及公司行动处理。信号分析价与实际成交/记账价分别管理，避免复权收益和分红重复记账。
- [ ] 增加现金与持仓账本，支持部分成交、未成交、退出及回测末期估值；净值按日估值，完整保留每只股票，移除仅留前3只的复盘限制。
- [ ] 模型化停牌、可卖持仓、涨跌停与成交量约束；不从日线高低价断言盘中可成交。板块、日期、证券状态规则以可追溯数据和官方规则核实后实现。
- [ ] 费用按实际成交金额和买卖方向记账，定义滑点、最低费用、初次建仓和退出费用；增加基准、成本与资金规模敏感性报告。
- [ ] 将理论多空分层收益保留为研究诊断，不暗示可以无约束融券交易。

验收：每日现金+持仓市值=权益；权益变化与损益/费用/资金流逐笔对账；未来数据改动不影响此前信号和成交；缺失行情、停牌、无法成交、现金不足等边界有明确结果；相同快照与配置可重复得到一致结果。

主要位置：qsys/strategy_backtest.py、qsys/factor_eval.py、qsys/signals.py及新增的共享账本/执行模型模块（具体拆分实施时确定）。

## 阶段四：独立验证与报告闭环（P1）

交付：每个在用策略的版本化验证报告，包括未通过原因。

- [ ] 固定训练、验证、独立留出区间，按收益标签跨度处理边界隔离；权重、方向、阈值和预处理参数仅在允许的训练数据上确定。
- [ ] 使用已有walk-forward、holdout、shadow、市场状态、数据时点和搜索校正规则；记录因子发现/修改时间，不把发现前的回放冒充发现后观察。
- [ ] 记录搜索次数、候选和淘汰结果；历史记录不完整时标记证据不足，不把批内FDR当作全实验校正。
- [ ] 固化report_id、配置/代码/因子/策略/规则版本、可复现数据快照引用、数据源、股票池快照、时间区间和成本模型；只有摘要哈希而无快照引用不足以保证复现。
- [ ] 输出IC/Rank IC定义、样本量、分层收益与单调性、换手、成本前后绩效、年度/市场状态表现、缺失覆盖与风险集中情况，优先提供表格和可导出明细。
- [ ] 对active/shadow策略逐个落库报告；评分有效、验证通过、交易批准分开，沿用现有交易硬闸，不因工程升级自动放行。

验收：报告可以从配置和快照重放；每个目标策略都有通过、失败或证据不足的结论；新旧规则对比解释清楚。真实观察期和缺失历史数据不能以代码验收代替，无证据就保留研究状态。

主要位置：qsys/validation_policy.py、qsys/execution_gate.py、qsys/scheduler.py、qsys/library.py及报告存储。

验收：图上数值与报告/交易账本一致；信号时间与成交时间不混用；跨训练/验证边界清晰；小屏和长区间交互可用。

## 执行批次与停止条件

1. 第一批：阶段一。先用手算案例锁定错误，再提取共享计算并修正现有入口。
2. 第二批：阶段二。只读排查后小批量验证，达到连续调度验收再扩容量。
3. 第三批：阶段三。先可核账的日频多头执行模型，再增加交易约束和敏感性分析。
4. 第四批：阶段四。真实在用策略重验、版本报告归档和旧结果迁移说明。
5. 第五批：阶段五。最后接图，不提前重做行情界面。

每批按实现范围跑已有回归与新增关键测试；先使用临时数据库/固定数据样例，再做有上限的真实运行。实施前备份受影响表并保留历史回执，使用可回退迁移；不得覆盖当前未提交修改。发现数值不对账、未来信息泄漏、版本错配或数据不足时，停止扩大运行范围并保留失败报告。阶段用验收结果推进，不承诺无法由开发加速的样本外观察完成日期。
