# 因子回测三阶段修复（2026-09-24）

## 第一阶段：纠正评分和样本诊断

- 区分有效研究评分、样本不足、数据异常和计算失败；空评分不能视为完成。
- 沿用 validation_policy 类型样本门槛（通常 250 日，部分事件类型 120 日），不为短历史数据降低门槛。
- 训练 IC 排除跨越训练截止日的标签，多周期收益只从训练段价格计算。
- 训练窗为空时保留已有 OOS 诊断。发现后/定义修改后的观察期独立计时。
- 历史无版本证据的评分标记 legacy_unverified，不能冒充新版验证。修改因子先归档历史评分，再使旧指标失效。

## 第二阶段：统一研究评估队列

- SQLite 持久队列按因子版本与股票池去重，进程锁避免重复计算。
- 注册新因子/修改因子入队；挖掘整批成功后请求一次合并处理，定时窗口继续兜底。
- 因子类型轮询，类型内优先处理在用策略因子。每块最多 5 个，整批最多 100 个；600 秒预算在块间检查，不强杀正在计算的块。
- 同版本同股票池同日不重复；有效/样本不足 7 个自然日后可重评，错误按 2/4/7 日退避，连续 3 次错误阻塞。
- 修复后可用 retry_blocked(name,pool,version) 显式恢复，保留历史凭据。尚未提供页面恢复按钮。
- 保留现有定时配置；实际运行次数取决于启用窗口、新增请求、到期队列与互斥锁，不保证每天固定完成数量。

## 第三阶段：证据与可观测

- 保存定义版本、规则版本、股票池摘要、数据摘要、训练截止日、首次发现/修改时间、成本与前瞻期、指标及诊断。
- 自动策略组包仅选当前版本且新版评分有效的证据，仍须独立验证与交易审批。
- workflow 与 factor-stats 显示中文进度/结果；浏览器通过 SSE 接收，支持断线游标回放和跟随底部滚动，无定时整页刷新。服务端每 2 秒读取持久事件日志。
- 当前方案的 valid 仅表示研究评分数据可用，不表示因子有效、无过拟合或具有实盘资格。
