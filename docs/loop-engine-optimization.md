# 进化体系优化方案（对标中金 Loop Engineering 因子挖掘框架）

> 目标：在**不推翻** RD-Agent 闭环的前提下，把文章的工程化机制分级接入，形成"双引擎"进化体系。

## 一、文章框架 vs 我们现状（差距诊断）

| 机制 | 文章做法 | 我们现状 | 差距 |
|---|---|---|---|
| 循环调度 | Loop 命令每 5 分钟一轮，每轮 ~30 候选 | RD-Agent 每轮 1 个假设（3-10 分钟），CoSTEER 子迭代 | **吞吐量差 30 倍** |
| 生成策略 | 表达式树五维演化：变异25%/交叉25%/扰动15%/随机15%/LLM引导20%，**预算随库状态自适应** | LLM 自由假设驱动，无结构化遗传操作 | **无表达式树演化** |
| 反同质化 | FSA 频繁子树规避（骨架>15% 禁复用）+ 同构参数变体上限 + 失败模式库 | 无（进化因子可能同质扎堆） | **缺失** |
| 机制覆盖 | 13 机制族追踪，LLM 引导优先补空缺族 | 无机制族概念 | **缺失** |
| 质量闸门 | **11 项硬过滤**（\|IC\|>0.03、两年超额>0、两年夏普>0.5、Calmar>1.0、近9/12月超额>0、相关<0.70） | RD-Agent 的 LLM 反馈裁决（软） | **软闸门 → 硬闸门** |
| 双 LLM 分离 | 生成 sub-agent 与审查 sub-agent 隔离（防自我说服） | 假设/编码/反馈同一模型 | **缺失** |
| 数据驱动分布 | 字段权重随有效因子自动调整（overnight 4x） | 无 | 缺失 |
| 检查点 | 哈希集合+原子写入，任意断点续跑 | RD-Agent __session__ 断点（已有 ✓） | 相当 |
| Hook 摘要 | 每轮自动输出因子库状态摘要 | 有经验报告（可扩展） | 部分 |
| 复合因子 | Top5 方向修正等权复合，Sharpe 3.14 | 策略包机制（已有 ✓） | 相当 |

**核心结论**：我们的"验证/评估/看板/经验"体系已经强于文章（11 项硬闸门我们的体检+OOS 已具备大部分），真正的差距在**生成层**——LLM 自由假设 vs 结构化演化。

## 二、优化路线（P1 → P4，逐期可用）

### P1：评估端硬化 + 因子哈希检查点（1-2 天，性价比最高）

1. **11 项硬闸门模块**（`qsys/gates.py`，复用现有 factor_eval 原语）：
   - `|IC| > 0.03`
   - 分年超额 > 0（2025 / 2026 各算）
   - 分年夏普 > 0.5
   - Calmar > 1.0（年化超额/最大回撤）
   - 近 9 月、近 12 月超额 > 0
   - 与库内因子 IC 序列相关性 < 0.70（低于即去重）
   - 换仓频率 5 日、单边千一成本（与文章口径对齐）
2. **因子哈希检查点**：全部测过因子的结构哈希集合落库（`tested_factor_hashes` 表），重复结构直接跳过不浪费回测；原子写入。
3. **入库改写**：RD-Agent 产出的因子不再"LLM 说接受就接受"，必须过硬闸门才标记 `accepted`——这就是文章"LLM 生成与硬编码验证分离"的精神（生成软、验证硬）。

### P2：反同质化三件套（FSA + 失败模式库 + 机制族）（2-3 天）

1. **结构骨架提取**（`qsys/structure.py`）：解析因子代码 → 算子序列 + 字段使用签名（如 `sub(ma(overnight,N),delta(...))` → 骨架 `sub-ma-delta@overnight`）。
2. **FSA**：统计各骨架在库内出现频次，**>15% 列入冻结名单**，新生成因子命中冻结骨架直接拒绝；同骨架参数变体上限 3 个。
3. **机制族分类**（13 族）：跳空/振幅/上下影线/量价背离/动量/反转/波动/流动性/趋势/价格位置/资金流/统计/形态。因子库打族标签，展示**族覆盖矩阵**（哪些族空缺）。
4. **失败模式库**：被闸门拒绝的因子骨架入库，生成阶段自动排除；并统计"高频失败骨架"展示。
5. **Hook 摘要**：每轮结束输出因子库状态摘要（族覆盖、FSA 冻结名单、入库率曲线）——接到现有经验报告。

### P3：表达式树演化引擎（双引擎之第二引擎）（4-6 天，核心）

新建 `qsys/loopengine/`（跑在 QSYS 容器或独立容器，走 qlib 数据）：

1. **表达词汇**（与文章对齐）：
   - 算子（14）：`sub/div/mul/delta/ma/ts_min/ts_max/ts_rank/decay_linear/corr/skew/roc/rank_cs/abs`
   - 字段（13）：`open/high/low/close/volume/amount/vwap/overnight/amplitude/upper_shadow/lower_shadow/hl_ratio/body_ratio`
2. **五维生成 + 自适应预算**（规则照抄文章并参数化）：
   - 变异 25%（换叶子/子树）、交叉 25%（两父本换子树）、参数扰动 15%（窗口微调，动量引导步长）、随机探索 15%（特征分布引导）、LLM 机制引导 20%（优先空缺机制族）
   - **自适应规则**：富矿脉（近期入库率高）→ 变异/扰动 +10%；相关性去重多 → 随机/机制 +10%；入库率连降 → 交叉 +10%
3. **数据驱动字段分布**：统计入库因子字段频次，生成权重向富矿字段倾斜（如 overnight ×4）。
4. **节奏**：调度器每 5 分钟一轮，每轮 30-50 候选 → P1 硬闸门 → 入库（目标对标：成功率 ~0.5%，日均新增 3-8 个高质量因子）。
5. **审查规则**（生成后置）：跨量纲拒绝、同质算子化简、最小复杂度、深度上限 6 层。
6. 与 RD-Agent 的关系：**双引擎共存**——RD-Agent 负责"研究型假设"（高层语义创新），LoopEngine 负责"高通量结构演化"（工程化扫矿），产物统一进 `factor_registry` 并打 `engine` 标签（rdagent / loopengine）。

### P4：双 LLM 分离 + 复合因子追踪（2 天）

1. **生成/审查 sub-agent 分离**：生成调用（创造性 prompt）与审查调用（严格边界 prompt）独立 DeepSeek 会话，审查抽样精判表达式边界（复用现有 DeepSeek 通道）。
2. **Top5 复合因子**：对入库因子按夏普取 Top5，方向修正后 z-score 等权合成，跟踪复合 IC/夏普/年化超额（文章口径：Sharpe 3.14 为目标参照）。
3. 复合因子作为特殊策略包进 `strategies` 表，挂定时任务每日出名单。

## 三、预期效果（参照文章量级）

| 指标 | 我们现在 | 优化后（目标） |
|---|---|---|
| 候选吞吐量 | ~1 假设/5分钟 | 30-50 候选/5分钟 |
| 因子库独立性 | 无相关性约束 | 全库 IC 相关 <0.70 |
| 同质化控制 | 无 | FSA 骨架>15% 冻结 |
| 接受标准 | LLM 软裁决 | 11 项硬闸门 |
| 复合因子 | 手动组合 | Top5 自动合成跟踪 |

## 四、风险与注意

1. **双引擎资源争抢**：RD-Agent 回测（local_qlib 重活）与 LoopEngine 高吞吐回测并存时，12 核 CPU 需要限流（LoopEngine 回测用向量化 pandas，不进 docker，单次 <100ms，可控）。
2. **文章成功率 0.41% 是常态**：不要预期大量入库；硬闸门的价值恰在于宁缺毋滥。
3. **数据边界**：日频量价是天花板（文章自己也承认），后续再接基本面/分钟数据扩字段。
4. 文章的 overnight 类因子在 A 股 2025-2026 特别强是**阶段性现象**，自适应预算可能让库也向 overnight 倾斜——FSA 机制就是解药，阈值参数要保守（15% 照抄起步）。

## 五、建议实施顺序

**P1 + P2 先行**（一周内核心里程碑：硬闸门 + FSA + 机制族），P3 作为主体工程第二期，P4 收尾。每期独立可交付。
