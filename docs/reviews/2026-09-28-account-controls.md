# 2026-09-28 存量敞口、降仓跟踪与交易归因修复

后续变更：用户随后明确要求无需审核，已启用自动模式。当前行为见 [自动降仓启用记录](2026-09-28-automatic-reduction.md)；下文保留最初人工确认版本的实施过程。

## 已实现

### 存量敞口闸门

- 买入提交和成交复核均检查账户全部股票的持仓及未成交买单。任一单股超过既有 15% 限额时，暂停全部新增买入，不能绕道买入其他股票。
- 风控调度识别单股和账户总仓位超限时关闭买入闸、撤销未成交买单；卖出保持原有 T+1、行情新鲜度、交易时段与可卖股数检查。
- 资金账号新增“账户超限检查与降仓执行”：显示市值、权重、限额、待成交买入额、超限金额、行情与风险目标是否就绪。

### 明确确认后的模拟降仓

- 方案和明细存入 SQLite，生成/刷新不下单。用户在页面审核明确数量并勾选确认后才能提交模拟卖单。
- 先处理单股超限，再满足账户总仓位目标；预留保守费用余量，按数量规则生成明细。手动持仓与策略持仓都计入，AI 明细必须与柜台股数核对一致。
- T+1/可卖数量不足时拆分可提交和受限数量，受限部分保留原因，不会消失或冒充完成。
- 方案绑定日期、账户资金/持仓/策略批次/未完成委托摘要与目标仓位。账户变化、跨日、目标变化、缺行情/风险评估、参考价变化超过 2% 时拒绝提交，要求重新生成审核。
- 方案提交记录、委托、成交及策略减记共用事务；重复/并发提交同一方案不会再次下单，写入失败回滚。
- 状态按关联委托及实际成交数量计算：待审核、等待成交、部分成交、受限、失败、撤销和计划数量完成。其他卖单不计入该方案；计划数量完成仍提示复核剩余风险。
- 新增手动风险核验入口，可能撤销违规买单但不卖出持仓，不调用 LLM。模型意见失败不再清空已经生效的确定性风险目标。
- 调度生成的只读建议与可执行方案共用数量计算基础；设置页明确引导到资金账号审核，不再暗示建议已经执行。

### 归因快照

- 新订单保存策略版本哈希、因子内容快照、信号批次引用、下单原因及可选降仓方案 ID；成交列表通过订单关联展示这些字段。
- 有 pick_id 时保存 `pick:<id>`；缺少 pick_id 时保存 `position:<id>` 作为任务引用，不伪造原始选股批次。
- 新 AI 开仓无法保存策略快照时拒绝提交；挂单成交前再次验证策略版本，版本变化不能沿用旧委托成交。
- 卖出沿用买入订单的版本、因子快照和来源，不以当前最新策略覆盖历史。
- 手动订单标为手动委托；旧记录、对账补记及无法唯一确认买入来源的仓位标为历史来源未完整记录。没有回填猜测的历史策略版本。

## 使用与边界

进入资金账号 → 账户超限检查与降仓执行。风险目标缺失时先更新风险评估，再生成方案，审核数量、参考价和受限原因，勾选确认后提交模拟降仓；刷新状态查看实际执行结果。

没有默认开启自动卖出。方案数量不是收益保证，也不是消除真实历史亏损。归因字段支持以后复盘，不意味着已恢复历史缺失的因子来源或完成因子绩效评价。
